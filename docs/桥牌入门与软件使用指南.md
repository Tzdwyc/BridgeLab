# 桥牌入门与 BridgeLab 使用指南

本文面向第一次接触桥牌的读者。先了解一副牌的目标和流程，再用 BridgeLab 与机器人完成一副牌，并在牌后分析中复盘。本文介绍的是常见合约桥牌规则；具体叫牌含义取决于搭档事先约定的体系。

## 一、桥牌是什么

桥牌由四人进行，面对面坐成北、东、南、西四个方位。北与南是一队，东与西是另一队。使用一副不含鬼牌的 52 张牌，每人 13 张。每副牌分为叫牌、打牌和计分三个阶段。桥牌不是各自为战：你要和搭档一起决定由哪一方做庄、打什么定约，并合作完成目标。[ACBL 桥牌基础](https://www.acbl.org/learn/)

牌张点数从大到小是 A、K、Q、J、10、9、8、7、6、5、4、3、2。四种花色是黑桃 ♠、红心 ♥、方块 ♦、梅花 ♣。黑桃与红心称为高花，方块与梅花称为低花。无将 NT 表示本副没有将牌花色。花色在打牌时没有固定大小顺序；只有成为将牌的花色才有压过其他花色的能力。

### 一副牌的流程

1. 发牌后，每人拿到 13 张牌。
2. 四人轮流叫牌，描述牌力、牌型和想打的定约。
3. 叫牌结束后，最终定约的一方尝试完成目标；另一方防守。
4. 逐墩打完最多 13 墩，按定约、实得墩数和局况计分。

## 二、叫牌：决定目标

叫牌不是随意报出想拿几墩。每个数字和花色合在一起构成一个叫品，例如 1♠、3NT 或 4♥。数字叫阶，表示承诺拿到的墩数下限；花色或无将表示定约将牌。叫品中的阶数不包括最开始自动归给双方的 6 墩，所以：

- 1♠ 要拿至少 7 墩；
- 3NT 要拿至少 9 墩；
- 4♥ 要拿至少 10 墩；
- 6♦ 要拿至少 12 墩。

同一阶中，合法叫品的花色顺序是 ♣、♦、♥、♠、NT；叫品也可以跳到更高阶。依次还有 Pass（不再提高本方承诺）、Double（在符合规则时加倍对方定约）和 Redouble（再加倍）。初学时可以先理解并练习自然叫品与 Pass；加倍和人工约定应按体系卡学习，不要只看叫品外形猜意思。

叫牌按顺时针轮流进行。一次叫牌有了实际叫品后，后续连续三家 Pass，叫牌便结束；如果四家一开始都 Pass，则本副流局，没有庄家和打牌。最高的有效叫品决定定约；加倍状态也可能影响分数。

定约的叫牌方称为庄家方，另一方称为防守方。最终定约花色由哪位牌手最先叫出，该牌手就是庄家。庄家的同伴称为明手。庄家左手边的防守方先打首攻；首攻打出后，明手把 13 张牌全部摊开，由庄家同时替自己和明手选择牌。

叫牌主要是搭档间的信息交换，而不是直接保证某个精确牌力。常见入门体系会用高牌点估算牌力：A=4 点、K=3 点、Q=2 点、J=1 点。长套、牌型、局况和搭档已经表达的范围也会影响决定。任何约定都必须由搭档共同理解；同一个叫品可能在不同拍卖进程中有不同含义。

## 三、打牌：争取每一墩

每墩由四人各打出一张牌组成。首攻者先出牌，其余三家依次跟牌。只要手里有首引花色，就必须跟该花色；没有该花色时，可以垫其他花色，也可以出将牌。没有将牌的墩，由首引花色中点数最大的一张赢；含有将牌的墩，由最大的一张将牌赢。赢下一墩的一方取得下一墩的首引权。[世界桥牌联合会《复式桥牌规则》第 44 条](https://www.worldbridge.org/wp-content/uploads/2017/03/2017LawsofDuplicateBridge-paginated.pdf)

以 4♠ 为例，庄家方的目标是至少拿 10 墩。若首引的是红心而庄家没有红心，可以用黑桃将吃；若这一墩出现黑桃，最大的黑桃赢墩。无将定约没有将吃机会，必须靠首引花色的大牌和长套兑现赢墩。

初学时可依次做这些事：

- 数明手和自己手中的大牌：A、K、Q、J；
- 每墩先确认首引花色，再判断是否必须跟牌；
- 估算自己一方还需要多少墩，并留意已赢墩数；
- 庄家同时规划自己与明手的出牌，避免把两手之间的进手过早用完；
- 防守时记住搭档公开打出的牌和已经出现的缺门信息。

叫牌中承诺的墩数是底线。多拿的墩称为超墩，少拿则称为宕墩。能否拿到一墩不仅取决于手里最大的一张牌，也取决于谁先引牌、花色长度、将牌控制和后续进手。

## 四、计分入门

本软件使用复式桥牌的原始分，以南北一方为正负方向累计；没有与其他牌桌比较，因此不是 IMP 或 MP 赛制结果。局况会影响奖分和宕分，不改变跟牌或赢墩规则。[ACBL 计分与学习资料](https://www.acbl.org/learn/)

不加倍且完成定约时，叫牌部分每墩的基本分为：梅花或方块 20 分，红心或黑桃 30 分；无将第一墩 40 分，之后每墩 30 分。叫牌部分达到 100 分会获得成局奖分；未达到则获得部分定约奖分。比如非局况下完成 4♠，叫牌分为 4×30=120，另加 300 成局奖分，合计 420 分。完成 3NT 的 9 墩，叫牌分为 100，非局况下加 300 成局奖分，合计 400 分。

6 阶定约叫成并完成称为小满贯，7 阶称为大满贯；满贯有额外奖分。未完成定约会给防守方宕分。加倍、再加倍、局况和超墩会改变分值，初学者可先用软件记分卡核对结果，再逐步学习完整计分表。

## 五、开始使用 BridgeLab

### 电脑端启动

1. 从公开仓库下载项目，或使用 Git 克隆：

   ```powershell
   git clone https://github.com/Tzdwyc/BridgeLab.git
   ```

2. 安装 Node.js 22.12 或更新版本。
3. 进入 `versions/v0.3.3` 目录，安装依赖并构建：

   ```powershell
   npm install
   npm run build
   ```

4. Windows 用户双击 `启动BridgeLab-v0.3.3.cmd`；也可以在该目录运行 `npm start`。浏览器会打开 `http://localhost:5193`。保留启动窗口，关闭它会停止本地服务。
5. 首次加载完成后，等待页脚显示“离线资源已缓存”。之后该浏览器可离线继续使用。Chrome 或 Edge 支持安装为应用。

如果已经有打包好的桌面应用文件夹，也可以直接双击启动脚本；只有从 GitHub 源码重新构建时，才需要先运行依赖安装和构建命令。

### Android 版

当前 Android 包在 `versions/v0.3.3-mobile/release/BridgeLab-v0.3.3-mobile-android.apk`。在 Android 设备上下载 APK 并安装；系统可能要求允许本次安装来源。若自行从源码构建，请按该目录的 README 使用 PowerShell 7 脚本 `scripts/build-android.ps1`。不同 Android 设备的安装限制由系统设置决定。

### 开始一副随机牌

打开“牌桌”页后点击“开始游戏”。每副牌你固定坐南家，与北家搭档，对阵东西两位机器人。也可以点右上方“新牌局”，选择随机种子以复现同一发牌；从该窗口开始会重置当前累计原始分。每副结束后使用“下一副牌”继续，之前各副得分会留在记分卡中。

### 叫牌和打牌

轮到南家叫牌时，点击叫牌框中的合法叫品；想结束本方叫牌时点 Pass。机器人会按所选叫牌体系自动行动。最终定约和目标墩数显示在牌桌右侧。首攻后明手亮牌；轮到南家或南家控制的明手出牌时，点击一张合法牌即可。软件会阻止不合法的出牌，例如手中仍有首引花色却试图垫其他花色。

牌桌上方提供：

- “提示”：轮到你行动时请求叫牌或出牌建议；
- “悔牌”：撤回上一项操作；
- “重打”：保留本副发牌和种子，从头重新进行叫牌；
- “摊牌声称”：声称南北方从当前未完成墩开始可拿到的墩数。软件用本地 DDS 检查能否保证；机器人提出声称时，你可以同意结算或拒绝并继续。

### 调整设置

点击右上角齿轮打开“游戏设置”：

- 叫牌体系：默认是“SAYC＋2/1 进局逼叫＋RKCB 1430”；也可以选择“2/1 进局逼叫”或“精确制（暂缓完善）”。四家使用同一套约定。正在进行的一副保留开局时采用的体系，切换后从下一副、新牌局或重打时生效。点“查看完整体系卡与支持范围”可查每项约定和未实现边界。
- 打牌强度：基础档使用确定性安全打法；标准档和挑战档分别抽取 8 个或 24 个符合公开信息的未知手牌样本，再由本地 DDS 比较候选。机器人不会读取实战中的真实隐藏牌。初学者可先选基础或标准档。
- 机器人行动速度：可选从容、标准、快速或即时。

### 自定义牌例

1. 打开导航栏“牌例工作台”，选择要分配牌张的北、东、南或西家。
2. 点击牌张，将其分配给当前座位；再次点击已分给该座位的牌，可取消分配。换座位后继续分牌。
3. 观察四家计数和花色摘要。必须把 52 张牌全部分完、每家正好 13 张，才能保存或模拟。
4. 填写牌例名称、发牌人和局况，点击“保存牌例”；点击“保存并开始模拟”则进入牌桌，从该发牌人开始正常叫牌和打牌。
5. 已保存牌例可在右侧载入或删除。保存的牌例位于当前浏览器本地，不会自动上传到 GitHub。

### 逐墩分析和试打

牌局完整打完或完成声称结算后，结果区可以打开“逐墩分析”；四家 Pass 的牌局可以打开“双明手分析”。分析室也可从顶部“分析室”进入，并从下拉列表切换已保存牌局。

分析室会显示四家分别做庄时、各定约花色的双明手最高可成阶数，以及原局逐张时间线。选择某个位置后，可检查四家余牌、当前墩、全部合法候选牌和每种选择对应的庄家最终总墩数；用上一张、下一张、上一墩、下一墩、滑杆或自动回放浏览。你可以新建试打分支，从任意位置尝试不同出牌，或让 DDS 按双明手最优牌继续到结束。分支不会更改原局记录和累计得分。

双明手分析假设四家牌全部可见，双方之后都采用最优应对。它适合用来理解这副牌在已知全手牌时的最佳路线，不等于实战中能看穿暗手，也不能直接当作机器人实战错误或成功概率的证明。实时打牌机器人只根据叫牌、明手和已打出的牌推断未知手牌。

### 记分、保存和隐私

点牌桌右侧“查看记分卡”查看每副定约、庄家、实得墩数和南北原始分。全局南北累计分显示在顶栏。它是单桌原始分累计，不是复式比赛中与其他桌比较后的成绩。

牌局、设置、自定义牌例、分析档案和试打分支自动保存在当前浏览器的本地存储中。BridgeLab 没有账号、云端 AI 或联网牌局；公开 GitHub 仓库只公开代码和仓库文件，不会把使用者浏览器中的牌局上传。清理该站点的浏览器数据会删除本地记录。重要复盘可在分析室点击“导出分析”，保存 JSON；需要迁移时点击“导入存档”。

## 六、词汇速查

| 术语 | 含义 |
| --- | --- |
| 墩 | 四位牌手各打出一张牌形成的一轮，共最多 13 墩 |
| 定约 | 叫牌结束时的阶数、花色或无将及加倍状态 |
| 庄家 | 最终定约一方中最先叫出该定约花色的牌手 |
| 明手 | 庄家的搭档；首攻后亮出全部手牌，由庄家控制 |
| 首攻 | 叫牌结束后，由庄家左手边防守方打出的第一张牌 |
| 将牌 | 定约中的主花色；在含将牌的墩中最大将牌赢 |
| 局况 | 影响成局、满贯和宕分的计分条件；不改变牌张规则 |
| 双明手 | 分析时四家手牌全部可见的牌局计算方式 |
