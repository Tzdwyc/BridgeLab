# BridgeLab v0.3.3

BridgeLab v0.3.3 从已交付并保留的 v0.3.2 复制，在独立子目录继续审阅修订。它保留完整单机桥牌流程、逐墩双明手分析室、可交互试打分支、默认的 SAYC＋2/1 进局逼叫＋RKCB 1430 以及基础精确制。正常对局机器人只读取合法可见信息；完成、声称结算或全不叫以后，分析室才会使用保存的四家手牌。

本版沿用 v0.3.2 当前界面的牌桌内手牌、中央叫牌框及右上角定约与墩数布局。安卓工程位于同级的 `v0.3.3-mobile`，复用原有 Flutter 外壳并装入本版代码及离线 DDS 资源。交付状态及检查结果见本版测试报告。

## 启动

1. 安装 Node.js 22.12 或更新版本。
2. 双击 `启动BridgeLab-v0.3.3.cmd`。
3. 浏览器会打开 `http://localhost:5193`。请保留启动窗口；关闭窗口会停止服务。

发布包已经包含构建完成的电脑端应用，不需要执行 `npm install`。首次打开并看到“离线资源已缓存”后，可断网继续打牌，也可计算新的双明手分析。直接双击 `dist/index.html` 无法可靠启动 Worker 和离线缓存。

v0.1、v0.2、v0.3、v0.3.1、v0.3.2、v0.3.3 分别使用端口 5188、5189、5190、5191、5192、5193，可以同时运行。v0.3.3 使用独立的 `v3.3` 牌局、分析工作区、分析档案和 DDS 缓存键，不会自动读取或覆盖已冻结的 v0.3 浏览器数据；分析室仍可由用户手动导入旧版存档 JSON。

## 牌例工作台

主导航中的“牌例工作台”可以手工建立指定牌例：

- 先选择北、东、南或西家，再点击牌张分配；页面实时显示四家张数和分花色摘要；
- 只有 52 张牌全部分配、四家各 13 张且没有重复或非法牌张时，才允许保存或开始模拟；
- 可设置发牌人、局况和牌例名称，并在浏览器中保存、载入、修订或删除多个牌例；
- “保存并开始模拟”会从指定发牌人进入正常叫牌，再按现有规则打牌；完整打完、声称结算或全不叫后均可进入双明手分析室。

牌例库使用 v0.3.3 专属的 `bridgelab.deal-editor.library.v3.3` 存储键。自定义牌张、发牌人和局况会随当前牌局存档及分析档案一起保存，刷新、悔牌、重打和牌后重放不会重新随机发牌。

## 逐墩分析室

完成一副牌后，可从结果页或记分卡进入分析室。完整打完的牌显示全部 53 个位置；声称牌显示声称前实际打出的时间线并在声称处截断；全不叫牌可自行选择一个假设定约和庄家再从首攻前开始分析。页面提供：

- 原始牌局的双明手结果表，按 N／S／E／W 四个庄家和梅花／方块／红心／黑桃／无将五种定约展示最高可成阶数，并标出本局定约；
- 原局从首攻前到实际结束位置的完整时间线；
- 每一位置的四家剩余手牌、当前墩、已赢墩数和原局实际选择；
- 每张合法候选牌在双明手最佳攻防下的庄家最终总墩数、相对最佳牌的损失和预计原始分；
- 上一张、下一张、上一墩、下一墩、滑杆跳转和自动回放；
- 最多 12 条试打分支、撤回分支最后一张、从任意位置改牌，以及按 DDS 最优牌续打至结束；
- 分析自动保存、JSON 导入导出、整副计算取消、单位置超时恢复和最多 400 个位置的本地缓存。

所有等价最优牌都会保留。试打分支和分析游标独立于原始牌局，不会改变原始动作、结果或累计分。

结果表固定使用完整 52 张原始手牌计算，不随逐张游标或试打分支变化。数字表示最高可成的定约阶数，例如“4”表示在该庄家和定约花色下最多可取 10 墩；“—”表示不足 7 墩，不能成一阶定约。每格悬停说明会同时给出 DDS 的总赢墩数。

“损失 1 墩”表示该候选牌使行动方在此双明手局面下比其最佳候选少赢一墩；庄家方行动时对应庄家总墩数下降，防守方行动时对应庄家多得一墩。DDS 假设四家都看见全部手牌，因此分析结果用于牌后复盘，不代表实战中一定能找到该路线。

## 叫牌与打牌 AI

默认使用“SAYC＋2/1 进局逼叫＋RKCB 1430”，设置中也保留独立的“2/1 进局逼叫”和“精确制”。默认卡采用 SAYC 的自然开叫与竞争方法；未 Pass 且无干扰的二阶新花色应叫为 13+ HCP 并逼叫进局；`1M–1NT` 为 5–12 HCP 半逼叫。选择从下一副、新牌局或重打生效；正在进行的牌局继续使用开局时固定的体系。完整范围见 [叫牌体系说明](docs/BIDDING_SYSTEMS.md)。

打牌机器人先执行确定性安全规则，标准档与挑战档再从合法可见信息采样未知手牌并调用本地 DDS 比较候选；它不会读取真实隐藏手牌。v0.3.3 继承了对第三家“同伴当前领先”误判的通用修复，会根据已见牌张、公开明手和缺门信息判断何时盖大牌及使用哪一张。详情见 [第三家错误根因](docs/AI_ROOT_CAUSE.md)。

SAYC 一阶开叫通常需要 13 HCP；12 HCP 时按 Rule of 20 检查，HCP 加两门最长套张数达到 20 才开叫，因此五张红心的 5-3-3-2 型 12 点牌会开 `1♥`，不足条件的劣质 12 点仍 Pass。一阶低花开叫后，11–12 HCP 均型且没有可在一阶应叫的四张高花时，`2NT` 是邀请、不逼叫；13+ HCP（通常 13–15）用 `3NT` 直接成局；`5-3-3-2` 即使持五张开叫低花支持仍优先定量描述，本卡不采用倒置低花加叫。花色定约在公开确认至少 8 张配合后使用调整点：双张 1 点，单张 2～3 点，缺门 4 点，联手每超过 8 张一张将牌再加 1 点。满贯问叫使用 RKCB 1430，将牌 K 计作第五关键张，并支持对 5♣／5♦ 的加一级将牌 Q 问叫；确认五个关键张和将牌 Q 后，5NT 询问旁门 K，最低旁门 K 在六阶显示，没有旁门 K 则回到六阶将牌。SAYC 的一盖一续叫也包含二张回叫开叫高花：`1♥–1♠–2低花` 后，6～9 HCP、低花无四张配合且有两张红心时回到 `2♥`；10～12 HCP 应作合适邀请；一盖一后的未叫第四花色按约定逼叫一轮。

叫牌历史和叫牌框中的每个叫品都按当时拍卖上下文解释。说明直接列出自然或人工性质、点力范围、套长、配合与逼叫状态；体系未定义的非常规叫品会明确标作未定义，不再显示“范围详见体系卡”占位文字。电脑端悬停、触屏设备长按、键盘聚焦均可查看。

v0.3.3 修订根据 GPT 已审阅的公开叫牌上下文修复共性问题并校正具体说明，并在提示底部显示“v0.3.3 · 10月10日修订”作为可见版本标识。离线缓存改为自动更新并启用新的 `bridgelab-v0.3.3-r1` 缓存；从旧缓存首次升级时，浏览器完成下载后再次载入页面即可看到修订标识，之后的更新会自动接管。

同一个叫品会按实际角色解释：例如 `2♣` 可能是强开叫、自然争叫或自然续叫，`2♦` 可能是强 `2♣` 的等待应叫、转移叫或自然二盖一；本次专门修正了若干按叫品外形误套说明的路径；尚未实现的边界会明确标记，不能把测试通过理解为所有叫品均已覆盖。Stayman、转移叫、第四花色、弱二特征问叫、RKCB 问 Q／问 K及签约均分别显示其人工含义与后续义务。

v0.3.3 还修正三类续叫：默认卡的 `1M–1NT` 为 5–12 HCP 半逼叫，均型最低限开叫人可 Pass，非均型、四张第二套、六张开叫高花或 18–19 HCP 均型牌必须继续描述；开叫人展示第二套后，应叫人先比较公开可知的联手套长，已知 5-3 开叫高花配合优先于只有 4-3 的第二套配合；未 Pass 且无干扰的二盖一进局逼叫持续到本方成局，不能出现 `1♠–2♦–2♠–Pass` 或 `1♠–2♥–3♣–Pass`。

加倍按拍卖上下文分为技术性、负加倍、对 Michaels／Unusual 2NT 的实力加倍和惩罚性加倍。竞争后的惩罚性加倍采用保守门槛：必须有 4+ 张敌方将牌、至少两个将牌大牌、足够快速赢墩和点力；局况只调整一点 HCP 门槛，不替代防守牌型。

打牌阶段支持摊牌声称。玩家声称时会公开声称方余牌及已经公开的明手；机器人只在公开信息采样的 DDS 结果充分且一致时提出声称，由玩家查看摊牌后决定同意结算或拒绝并继续打牌。声称结算后显示声称时四家余牌，并允许进入逐墩分析；分析保留实际已打时间线，在声称处截断，不伪造未打出的牌。

黑桃和梅花使用两套轮廓、颜色均不同的自绘 SVG：黑桃为深蓝尖顶，梅花为绿色三叶形。叫牌框、叫牌历史、牌桌、墩记录和分析室共用同一套图形。

## 开发与验证

本次限定原始 10,000 副中此前未审阅的 2,000 副，没有扩大语料。当前聊天 GPT 及子代理逐步检查了冻结基线的全部 18,348 个叫牌步骤和说明，归纳后修复，再回放错误位置并复查完整长序列。此前 v0.3.2 的 1,920 副与本批无重叠；累计独立牌例审阅覆盖 3,920 副，仍有 6,080 副未审阅。这些数字描述不同版本基线上的人工模型审阅范围，不代表当前版所有新序列都得到重复审阅，也不代表零错误。

观察脚本只记录牌张、公开叫牌及程序输出，质量判定由 GPT 写入逐步记录；三份历史规则质量验证器仍不作为验收依据。固定回归检查保存 GPT 从当家手牌和当时公开拍卖选定的预期。具体修复、回放范围、保留的判断分歧和软件检查结果见 [本版测试报告](docs/TEST_REPORT.md)。

源码目录中可执行：

```powershell
npm install
npm run build
npm test
npm run test:e2e
```

DDS 原生参考程序的可复现构建脚本为 `scripts/build-dds-reference.ps1`。它需要 Clang C++ 工具链，仅用于独立验收；日常运行只使用浏览器内的单线程 WASM。测试证据和适用边界见 [测试报告](docs/TEST_REPORT.md)，架构见 [技术架构](docs/ARCHITECTURE.md)，第三方许可见 [第三方软件说明](docs/THIRD_PARTY_LICENSES.md)。

## 数据与隐私

牌局、设置、牌例库、DDS 缓存和分析分支均保存在当前浏览器的本地存储中。应用没有账号、云端 AI 或联网对局。清理 `localhost:5193` 的站点数据会删除 v0.3.3 的本地内容；重要分析请先导出带有 `BridgeLab-v0.3.3` 前缀的 JSON。
