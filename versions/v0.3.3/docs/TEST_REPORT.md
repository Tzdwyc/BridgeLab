# BridgeLab v0.3.3 验证与交付记录

## 版本与界面

本版使用独立目录 versions/v0.3.3 和端口5193。采用当前 v0.3.2 界面：手牌位于牌桌四方、叫牌框与叫牌进程位于牌桌中央、定约与墩数位于右上角。牌后历史通过“叫牌进程”打开，支持逐个叫品悬停和手机长按。新版调整版本标识和叫牌按钮的最小44像素触控区域。

## 2000副逐步GPT审阅

严格选取原10000副中此前未审阅的2000副：编号540–1206、4033–4699、7146–7811，使用原种子 v031-model-review-{编号}。原语料SHA256为 dd0e08988a9c5dc4c974b5ebb4b15f723704a09eaf3adeea12eb7ba91d113d19。选择、身份和无重叠记录见 artifacts/v033-review-selection.json。

冻结基线18348步，五个AI源码联合SHA256为 a7ee9885b5e92deaaccf691e8c6677692c8a362454f6e73f5ac4822ade1d1472。当前聊天GPT与三个子代理逐步阅读每个当家手牌、HCP、公开前缀、叫品和说明，亲自写下正确、错误或分歧判断与理由。没有用规则质量验证器、模型API自动评分或输出改变率代替模型审阅。

artifacts/v033-model-review-coverage.json 证明2000副及18348步均有明确逐步记录；脚本只检查编号、身份、摘要、完整性和重复，不决定质量。基线有729副双方竞争、317副至少12步的长序列，最长24步；这些观察统计不是通过率。

问题归纳为公开套长、点力范围、逼叫义务、邀请接受、差配合、竞争续叫、无将止张、加倍、RKCB退出与说明角色后集中修复。532个曾有叫品或说明错误判断的基线位置回放；包含后来被撤回的误报，不等于532个已证实错误。每轮重新记录相同2000副完整拍卖，没有扩大质量语料。

第一轮修复后GPT复查全部532个目标位置及40副完整新拍卖的475步。第二轮候选SHA256为9d040530f7ed08de1011958ab07657cb0dc27ce9509bb292a3337fabe2d1b0ee；同2000副生成19239步。532个位置再分为180、172、180条逐条复查，并继续复查原40副。记录见 v033-postfix-review-*.json、v033-postfix-complete-review.json、v033-final-review-*.json 与 v033-final-complete-review.json。

复查也纠正HCP计算、九张以上将牌调整点、最低合法竞争空间和已Pass应叫人的非逼叫例外。不能把最低竞争三红心当十点邀请，也不能把被回答的一轮逼叫继续算成逼局。自然一无将再叫后下一阶新套不逼叫，参考 [ACBL SAYC手册](https://web2.acbl.org/documentlibrary/play/sayc_book.pdf)；本卡没有新增低花逼叫。用户指定二盖一逼局、5–12半逼叫一无将及RKCB1430优先。

## 修复与边界

叫品说明与公开语义共用分类，修正第二套重复被误说六张、最低竞争回套被误说强跳、转移配合丢失、加倍回复被误说首次争叫、已Pass自然新套误逼叫、无将范围错套及人工询问未履行。强二梅花允许4441的四张自然低花；二盖一和强牌续叫不偷用真实同伴手牌。

无将与高花成局通常25点、低花通常29调整点，先确认配合再计短门及额外将牌。技术X最低被迫应叫可能零点，不能凭加倍方强牌自动签约。自由应叫须有真实实力。惩罚X需要敌将牌大牌质量及防守实力，不能只因HCP高就惩罚。

RKCB保留五阶同将牌安全Pass，避免非法重复后误跳六阶。0/3歧义只由自己已知大牌、同伴先前自然无将公开范围和全副40HCP上界来排除。确认全部关键张及将牌Q后才问旁门K，不读取同伴真实手牌。

本批与此前1920副无重叠，累计原语料审阅覆盖3920副，仍有6080副未完成GPT审阅。各阶段绑定不同源码摘要，不能说累计数字是当前最终源码的全部逐步复验，也不能把相同2000副的新观察步骤全部说成重新被GPT检查。轻争叫、牺牲和部分未约定高阶路线保留分歧，不宣称竞赛级或任何低级错误归零。
