# v0.3.5 安卓牌桌栈溢出修复验收

2026年10月16日。版本仍为v0.3.5，安卓内部版本码由37增加到38，支持覆盖升级。保留本轮技术性／惩罚性加倍、竞争扣叫及其他叫牌改进，不改v0.3.4原版或其修复包。

## 已查明并修复的问题

真实故障为第20副，种子d6753ea2-3fef-4cc7-be8d-93eecd089602，西Pass、北2H、东X，轮到南家。生成候选2NT说明时，逼叫解释器查询该2NT的人工性，人工识别兜底又查询同一前序和同一座位的逼叫状态，尚未得到结果就重复进入，最终栈溢出。牌桌会预先生成所有38个叫品说明，因此无需选中2NT即可触发。此处2NT实际合法；不可用按钮也必须安全解释，不能把问题归因于用户选择非法叫品。

修复将弱二特征询问提取为共享的纯前序识别函数weakTwoFeatureInquiryAt，不再借助逼叫解释器判断自身；并为弱跳争叫增加同样的weakJumpFeatureInquiryAt。没有种子特判，没有异常后返回Pass、空说明、清存档或递归深度上限。

严格回归另发现并修复两类共性问题：

- 弱跳争叫与2NT之间已有敌方X或自然争叫时，仍误启动人工特征问叫。现在只在本卡定义的无干扰条件成立时启用；成立之后遭X仍保留答叫义务，之后遭自然竞叫则不强制未约定的普通答叫。
- 已成立的RKCB 4NT被X后，初次关键张回应义务可能丢失。现在有明确keycard状态，X不解除回应；实际持两关键张带将牌Q的测试仍回答5S。没有添加未约定的DOPI／ROPI。

同一2NT按条件分别处理：无干扰弱二或弱跳后是人工一轮特征询问；上述询问前已受干扰的竞争2NT在现卡未约定，明确不赋虚构的邀请点窗、止张或人工逼叫。它不等于异常处理，也不把真正无干扰问叫禁用。六个重点说明另有当前GPT逐项判语：artifacts/stack-hotfix-tooltip-gpt-review.json。

49个运行时源文件与原交付ZIP逐一比较，仅src/ai/bidding-semantics.ts改变。bidding.ts、competition.ts、systems.ts和suit-evaluation.ts均与原v0.3.5相同。原200副完整重录后，1718步实际叫品、当家牌、公开前序及悬停说明逐字段完全一致；这是原GPT判语的严格观察一致性证明，不冒充一轮新的200副人工审阅。

## 依赖方向和终止条件

静态审计覆盖说明、人工识别、逼叫状态、加倍分类、无将点力和公开约束的8组依赖边。语义模块不导入决策器，说明不回调chooseBid。UI历史说明明确传入该历史叫品之前的slice；自然按钮每个为说明包装与title各求值一次，三个特殊按钮各一次，所以每个BiddingBox一次渲染有73次说明求值，不能仅测试选中的叫品。

终止依据是具体前序和查询阶段，而非函数名必须构成无环图：

- 当前询问是否成立先由纯前序事实判断，不允许问叫识别回查同一问叫的逼叫状态。
- 历史叫品按自身index截断；公开约束回读更早的叫品，NT范围回读更早的平台及此前约束，加倍查询此前被加倍的目标。
- RKCB当前4NT人工识别在明确的4NT分支由此前自然叫与配合事实直接返回，不再走同前序逼叫兜底；后续关键张、Q和K问答回读更早的问叫。
- 明确对历史API做追加合法后续后的冷缓存不变检查，覆盖publicCallMeaningAt、isArtificialBidAt、noTrumpRangeAt和classifyDoubleAt。

详见artifacts/v035-stack-semantic-audit.json与stack-hotfix-ui-call-contract.json。本轮未再发现可复现的同类循环；这不是对任意未知前序的数学完备性保证。
