# BridgeLab v0.3.6

本版新增首页、独立历史档案和双桌 IMP 比赛，沿用 v0.3.5 的新牌桌、修正叫牌体系及公开信息打牌 AI。v0.3.5 原目录保留。

## 启动

- 电脑端：双击“启动BridgeLab-v0.3.6.cmd”，打开 http://localhost:5196。需要 Node.js 22.12 或更新版本，游戏期间保留启动窗口。
- 电脑完整包：artifacts/BridgeLab-v0.3.6-source-and-app.zip。
- 安卓：安装同级 v0.3.6-mobile/release/BridgeLab-v0.3.6-mobile-android.apk。沿用包名和签名，版本 0.3.6、内部编号 40。
- 开发：npm install、npm run build、npm start。缓存完成后网页、DDS 与机器人均可离线运行。

## 两种玩法

首页提供“开始打牌”“历史牌局”，有进行中的牌局时可直接继续。牌例工作台、分析室和设置仍可进入。
累计总分：用户与三个机器人打牌，南北原始分连续累计，保留提示、悔牌和重打。随时结束并归档；单场最多 5000 副，之后可开新场。
双桌 IMP：用户固定坐主桌南家，北家是队友；参考桌东西是另两位队友。两桌的牌、发牌人、局况完全相同，参考桌四位机器人独立叫牌打牌。可选 8、16、24 副，默认 16 副。
每副用户队分差＝主桌南北分－参考桌南北分，逐副按标准 IMP 表转换后累计。例如 +420 与 +170 的差值为 +250，即 +6 IMP。参考桌在主桌结束后自动运行；留在牌桌等待结算，离开页面或打开弹窗时暂停。
正常 IMP 关闭提示、悔牌、重打；选择“辅助练习”可启用，档案会标明。双方完成后开放两桌结果、叫牌解释和逐墩分析。已结算 IMP 不能通过悔牌或重打改分。四家 Pass 和声称结算仍可复盘。

## 历史、备份与升级

新比赛自动归档上一场，未打完的记录也保留。继续已归档的未完成比赛时建立新的续赛标识，保留原档案。历史可导入／导出；安卓使用系统文件选择器，电脑使用浏览器文件功能。
新比赛固定体系和强度，记录软件版本；每次叫牌的说明按该比赛体系和原叫品之前的前序生成并随记录保存，以后升级不会重写这些原始说明。旧版未逐副记录体系，旧记录说明明确标为按归档时体系作参考解释。
同一站点地址／同一安卓应用升级时读取 v0.3.5 存档，保留旧键和原始备份，后续修改写入 v0.3.6。旧分析和自选牌例仍可读取，修改后写入新命名空间。
电脑浏览器按地址隔离数据。原来在 http://localhost:5195 打牌的用户，请先关闭旧服务窗口，再双击“从v0.3.5地址升级启动.cmd”，让新版在相同 5195 地址启动并迁移原记录。直接打开 5196 不会读取 5195 的存档；localhost 和 127.0.0.1 也不是同一站点。新旧版本不要同时向相同站点保存。
档案优先保存在本机 IndexedDB，当前进度保存在本地存储。禁用存储、清理站点数据或卸载应用可能删除记录，请定期导出。

## 验证边界

本版验收见 [测试报告](docs/TEST_REPORT.md)。含旧版本号的继承报告属于历史资料，不是本版新增审阅证据。
本轮没有重新训练叫牌网络，也没有宣称新的 GPT 牌例质量审阅；原有叫牌和打牌 AI 文件保持一致。两桌机器人只使用自己桌上的合法公开信息，DDS 复盘及声称裁定不回流实战策略。本机保存完整牌局，不能阻止主动读取本地存储。
手机尺寸和离线验证使用浏览器模拟；APK 构建、签名与资源已核验，真实设备安装升级、系统文件选择器和触控仍需实机确认。
