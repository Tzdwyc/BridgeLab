# BridgeLab v0.3.6 验收报告

本版实现首页、独立历史档案、累计总分和用户加七个机器人的双桌 IMP 比赛。保留 v0.3.5，不改动既有 AI。电脑端入口为 http://localhost:5196；同地址旧存档升级入口见 README。

## 已实现

- 默认进入首页，可开始打牌、查看历史或继续当前比赛。
- 累计总分连续打牌；双桌 IMP 支持 8、16、24 副，默认 16 副。逐副以主桌南北分减参考桌南北分，再查标准 IMP 表累计。
- 同副两桌牌张、局况和发牌人一致；主桌南北及参考桌东西属于用户队。参考桌四人独立运行，全部只观察本桌公开信息，使用独立 Worker。
- 显示双方 IMP 比分和净胜负；未结算参考桌的结果、手牌、叫牌和分析入口不开放。
- 普通 IMP 关闭提示、悔牌、重打；辅助练习明确标记；双方已结算后不得用重打修改成绩。
- 当前进度自动保存；历史优先 IndexedDB，并提供本地存储降级和失败提示。新比赛先归档上一场，恢复已归档未完成比赛保留原记录并建立续赛标识。重复导入、内容冲突和异步跨桌回写有保护。
- 旧 v0.3.5 会话原文和备份保留。分析与自选牌例读取旧键，编辑写新键。旧历史未记录逐副体系，解释明确标记参考性质；新比赛使用冻结体系和每步原前序。
- 两桌均可逐墩复盘；声称在实际出牌位置截断；ALL PASS 可建立假设定约分析。
- 安卓沿用包名、签名与本地来源，静默修复旧 Service Worker 缓存；不显示右下角诊断按钮。文件备份使用原生系统文件选择器，不依赖 WebView 下载 Blob 的默认行为。

## 历史失败及处理

首次完整验证因新目录未复制独立原生 DDS 对照程序，以及旧测试仍断言 v0.3.5 命名空间，出现五个失败；补齐程序和新版断言后全部 25 项受影响测试通过。

一次高并发完整运行的断言虽全部通过，进程因 Vitest onTaskUpdate 通信超时以 1 退出；该结果保存为 v036-parallel-unit-results.json，不计为最终通过。降低到单测试进程后，2277 项、原始退出码及未处理错误记录均通过，未提高测试超时上限。

一次界面回归误要求“只有一张合法牌”的局面也必须生成 DDS 样本。实际提示正确走强制出牌安全层；测试改为先执行强制出牌，抵达有多个合法选择的位置后，仍严格检查八个公开信息样本、DDS 引擎和合法建议牌。旧失败结果保存为 e2e-v036-before-choice-fix.json。

生成版本元数据时曾误改依赖锁文件中的 for-each 版本描述；已从旧锁文件恢复全部依赖描述，仅更新应用版本。实际安装依赖和运行资源未因此变动；冻结候选一的源快照与后续元数据区别有移动端说明，最终候选使用修正锁文件。
