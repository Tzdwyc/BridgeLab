# BridgeLab v0.3.1 技术架构

## 两条信息边界

正常对局和牌后分析采用不同的数据边界。

正常机器人只能接收 `BiddingObservation` 或 `PlayObservation`。`src/ai/observation.ts` 是游戏状态进入策略层的唯一入口：它传递控制方手牌、当前行动手牌、公开明手、叫牌、已打牌张和合法动作，不传递种子或未公开的其他手牌。叫牌策略和打牌策略位于 `src/ai`，不导入 DDS。

分析室只接收已经结束的牌局。完整打完的牌重放 52 张实际出牌；声称牌重放声称前的实际出牌并在声称处截断；全不叫牌由用户设置假设定约和庄家，从首攻前建立分析位置。此时四家真实手牌已属于牌后复盘数据，`src/analysis/adapter.ts` 将每一位置转换成 DDS 的 PBN 输入。这个隔离防止双明手求解进入实战机器人。

玩家声称由 `src/controller/claim.ts` 中独立的裁定入口把当前完整四家牌交给 DDS，结果只用于立即结算，不会返回实战机器人。机器人声称使用已经由公开信息样本产生的 `PlayDecision`：至少 8 个样本、全部支持所选牌且最终墩数一致时才提出；用户拒绝后执行预先保存的原定出牌并继续。核心 `claim` 动作只接收已经裁定的墩数，负责校验行动控制方、分配余墩、计分、保存、重放和悔牌。

## 原始牌局双明手结果表

分析页顶部的结果表使用 DDS `CalcDDtablePBN` 一次计算完整 20 格。输入始终来自保存的四家原始手牌，不使用当前游标的剩余手牌；因此移动游标、自动回放或建立试打分支都不会改变这张表，切换分析牌局才会重新计算。

DDS 原始矩阵轴为黑桃、红心、方块、梅花、无将 × 北、东、南、西。适配层把它明确转换成页面的北、南、东、西 × 梅花、方块、红心、黑桃、无将，且每格保留 DDS 返回的 0 至 13 总赢墩数。页面只把总墩数换算成最高可成阶数：7 墩显示 1，13 墩显示 7，不足 7 墩显示“—”。实际定约只按庄家与定约花色高亮一格。

## 实际位置时间线

`replayLine` 从保存的动作重新构造状态。普通牌局按种子重新发牌；牌例工作台创建的牌局则从 `GameRecord.customSetup` 中保存的四家手牌、发牌人和局况重建。首攻前是位置 0，每打出一张牌增加一个位置；完整打完时到位置 52，共 53 个状态。声称动作不会伪造成出牌，时间线止于最后一张实际牌；全不叫的假设分析只有首攻前位置。重放使用核心规则层的 `applyAction` 和 `playCard`，不会直接改写手牌或赢墩数。

DDS 的 `first` 字段表示当前墩首引者，而非下一行动者。适配器会从剩余手牌中扣除当前墩已经打出的 0 至 3 张牌，并验证 DDS 返回的候选集与核心规则计算的全部合法牌完全一致。

DDS 原始分值按当前行动方阵营计数。标准化层把它统一换算为“本副最终庄家总墩数”，再按行动阵营计算候选损失：庄家方取最大值，防守方取最小值。相同最优值的牌全部标记为最优。

## Worker、取消与缓存

`src/analysis/worker.ts` 在 Web Worker 中加载单线程 DDS WASM；主界面线程不执行同步求解。Worker 消息用 `position` 与 `table` 两种类型区分逐位置结果和 20 格总表，避免两类返回值混用。`AnalysisClient` 为单个位置和总表请求设置 30 秒上限，为 53 位置批量任务设置 180 秒上限。DDS 调用本身是同步的，因此取消或超时时终止整个 Worker，下一次请求创建新的 Worker。

逐位置结果以引擎版本、完整 DDS 局面、庄家方和已经取得的墩数组成的键写入本地 LRU 缓存，最多保留 400 个位置。总表使用只绑定引擎版本与完整原始 PBN 的独立内存缓存。读取结果时仍会验证引擎版本、合法候选覆盖或 20 格完整性、数值范围和最优标记；损坏或旧版本结果不会显示。存储空间不足只影响逐位置缓存，不影响当前真实求解结果。

离线资源由 Service Worker 预缓存，其中包括包含 DDS WASM 的 Worker 构建产物。测试覆盖断网刷新后清空 DDS 结果缓存，再对另一副未缓存牌局完成 53 个位置的计算。

## 分支与原局不变性

分析文档保存原始 `GameRecord`、原局游标、活动分支和最多 12 条分支。每条分支只记录起点与此后选择的牌张。显示时从原局状态重新调用核心 `playCard`，因此跟牌义务、行动座位和终局计分继续由核心规则验证。

在分支中回到较早位置并改出另一张牌时，只截断该分支的未来；原始 `GameRecord` 永远不改写。DDS 最优续打若有多张等价最优牌，会稳定选择第一张完成自动续打，但界面仍显示所有等价最优候选。

## 存档隔离

v0.3.1 牌桌存档键为 `bridgelab.session.v3.1`，牌例库为 `bridgelab.deal-editor.library.v3.1`，分析工作区为 `bridgelab.analysis.workspace.v3.1`，分析档案为 `bridgelab.analysis.archive.v3.1`，逐位置 DDS 缓存为 `bridgelab.analysis.cache.v3.1`。运行时只自动读取这些 v3.1 键；已冻结的 v0.3 数据不会被自动读取或覆盖。旧存档仍可通过分析室的显式导入流程读取。

牌例库独立保存最多 50 个已校验牌例。进入模拟时，核心层把指定牌张、发牌人和局况写入 `customSetup`，并继续使用与随机牌局相同的叫牌、合法出牌、计分和分析路径。保存、载入、悔牌、重打和分析重放都通过核心动作重新构造状态，避免编辑器绕过规则层。

v0.1、v0.2、v0.3、v0.3.1 分别运行在 5188、5189、5190、5191 端口。端口、v3.1 存储键和 `bridgelab-v0.3.1-r2` Workbox 缓存标识共同隔离各版的本地状态与离线资源。v0.3.1 使用自动更新；新 Service Worker 激活后立即接管客户端，避免提示说明长期停留在旧构建。
