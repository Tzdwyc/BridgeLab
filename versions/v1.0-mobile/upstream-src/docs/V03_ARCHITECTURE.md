# BridgeLab v0.3.1 架构与验收边界

## 本版目标

v0.3.1 在已冻结 v0.3 的基础上继续完善叫牌解释与续叫。v0.3 作为冻结版本保留，v0.3.1 使用独立目录、端口、浏览器存储、缓存和发布包。

## 叫牌语义层

叫牌决策不再只读取“最后一个叫品”。公开拍卖会被解释为点力范围、自然或人工含义、已知配合、最近一次无将范围，以及 `none`、`one-round`、`game` 三种逼叫状态。

花色定约只有在公开确认至少 8 张配合后才从 HCP 切换为调整点。双张计 1，单张按 3 张支持或 4+ 张支持计 2／3，缺门计 4；公开可知的联手将牌超过 8 张时，每多一张计 1。满贯问叫采用 RKCB 1430：将牌 K 与四张 A 为 5 个关键张，并实现 5♣／5♦ 后的加一级将牌 Q 问叫。

SAYC 的一阶开叫以 13 HCP 为通常门槛；12 HCP 牌使用 Rule of 20，以 HCP 加两门最长套张数是否达到 20 决定开叫，避免既漏掉有正常描述价值的 12 点五张高花，也避免把所有劣质 12 点无条件放开。

以下条件属于硬错误，测试必须为零：

- 未解除的一轮逼叫或进局逼叫选择 Pass。
- 把 Stayman、转移叫、强 2♣ 等人工叫品当成最终定约。
- 已公开的再叫范围丢失，例如把 `1♦–1♠–2NT` 仍按最低开叫计算。
- 自然争叫对手已经叫过的花色。
- 明确达到成局或满贯实力后停在过低定约。

## 实战打牌信息边界

`observe()` 是牌局状态到策略的唯一入口。它只包含行动方手牌、已公开明手、叫牌、已打牌张、各家剩余张数、当前墩和比分。真实隐藏手牌和牌局随机种子不会进入实战分析 Worker。

实战决策分为两层：

1. 确定性安全层处理跟牌、最小够大、同伴稳拿、最小将吃或超将、二家低放、保护明确赢张和止张，以及策略异常后的合法回退。
2. 标准和挑战强度从公开信息生成与已知缺门、手牌张数及基础开叫范围一致的隐藏牌样本，再逐样本调用本地 DDS，对所有合法候选按成约或击宕概率和期望墩数排序。

采样随机种子只由规范化公开观察生成。同一公开局面必定得到同一批样本；替换真实隐藏手牌不会改变观察、样本或决策输入。

采样 DDS 属于 PIMC 近似，会受到策略融合限制，因此产品不会把它描述为“完美实战”。双明手复盘仍使用真实四家牌，和实战采样严格分开。

玩家可以在自己或自己控制的明手行动时声称余墩。声称窗口公开声称方余牌及已经公开的明手；该请求使用隔离的完整四家牌 DDS 裁定，超过可保证墩数时不改变牌局。机器人只有在公开信息采样至少 8 份、全部样本支持同一候选且最终墩数完全一致时才提出声称；用户查看摊牌后决定是否接受，拒绝后继续执行机器人原定出牌。声称牌局保存实际已打动作和一个终局声称动作，不伪造剩余牌张；牌后分析重放真实出牌并在声称处截断。

## 牌例工作台

牌例工作台允许给四家逐张分配 52 张牌，设置发牌人和局况，并命名保存多个牌例。只有四家各 13 张、52 张无重复且牌张合法时，牌例才能保存或开始模拟。

自定义牌例进入与随机牌相同的合法叫牌、完整打牌、计分和逐墩双明手分析流程。自定义初始手牌会写入牌局记录，因此刷新、悔牌、重打和分析回放都能还原同一牌例。

## v0.3.1 硬门槛

- TypeScript 检查和生产构建通过。
- 所有核心、叫牌语义、打牌安全、采样信息边界、牌例持久化和浏览器端流程测试通过。
- 确定性低级错误目录零失败；测试必须按不同语义局面计数，不能只用座位或花色变换凑数量。
- 所有机器人动作合法；异常回退也必须经过叫牌语义或打牌安全层。
- 公开观察的隐藏手牌置换测试零差异。
- Chrome 和 Edge 桌面布局可用；离线构建包含 DDS WASM 和 Worker。

“任何低级错误”在本项目中指上述可机械判定的不变量。桥牌高级路线没有有限规则可以保证所有牌例最优，实际牌力另以固定牌例集的平均损墩、灾难性损墩率和成约或击宕率衡量。
