# v3.2.2交付验收

本版按用户确认的两项修改执行：修正并精简叫牌注释，以及手机打牌信息布局。基于已验证的v3.3.1，版本名按要求使用v3.2.2；Android内部版本代码60，高于上一版59，可覆盖升级。

## 叫牌注释

统一单机按钮、叫牌记录、联机、分析室与历史牌局的解释入口。说明依据叫品当时的公开前序，不读取真实暗手或后面的叫品。重点修正了混入其他答叫方案、无依据的点力推断、人工叫与自然叫混淆，以及逼叫、邀请、加倍、配合和止张来源的遗漏。用“点”“二十法则”等自然表述代替程序式缩写。

已复核既有108副冻结牌的1,034个叫品、33类公开角色及174行跨体系前后对照。平均说明由40.26字缩为28.59字，最长由223字缩为92字。14个现有体系未定义的续叫明确标记为未约定，没有补造点力范围。已知且一致的历史约定刷新显示文字；版本未知或不匹配时保留原存档说明，不改写历史数据。

核查详情及前后示例见[V322_BIDDING_ANNOTATION_AUDIT.md](V322_BIDDING_ANNOTATION_AUDIT.md)。两份历史注释表175项保留全部前序、叫品和用例名称；其他旧文字断言按同一事实更新，决策及结构化断言没有为通过测试而改动。

有一处既有合同冲突需要保留说明：强2♣–2♦等待–3♦后的二次负应，旧内部分析字段及部分旧文字仍采用3NT，而用户已批准3♥为0–3点人工二负、3NT为4点以上自然正应。本版显示按已批准约定校正，底层字段与实际叫品选择保持上一版原样。这项内部不一致仍然存在，不能把本轮注释修正说成已经修复其选叫行为。

## 手机布局

定约、庄家、两方得墩柱及成约进度合在本人手牌下方的同一区域。原墩数柱与目标线保留，目标文字放在庄家柱下，避免遮挡另一方得墩。实时使用“还差几墩”“已够墩”等短句，结算显示“成约”“超几墩”“宕几墩”。各座位的余牌数字隐藏。

单机与联机共享信息组件；南北／东西计数不随观看座位旋转。底部四导航固定，中间内容滚动，自家单排手牌、明手四花色竖列、完整叫牌及“叫牌记录”“上一墩”保留。窄短屏以中部滚动代替压缩牌桌，北、西标题不再重叠。

第一轮自动检查8项通过，但原生截图复核发现短竖屏座位标题及部分目标文字相遮。两处实际缺陷已修复，旧截图、结果和修复记录保留。随后Android实际短屏发现复盘按钮末端裁切，已在手机样式中补足滚动末端空间，并允许信息区完整显示。最终手机浏览器9项通过，覆盖320／360／430竖屏与横屏、真实短屏320×579、短屏标题框、南北与东西目标数字、声称结算及长叫牌滚动；在最大滚动位置，两个按钮必须完整位于主内容和导航边界之上。截图位于`artifacts/v322-ui`。

另有6项实际生产页面检查通过：单机同一D按钮由一阶换二阶时重新解释；联机同一位置换前序、体系与牌局时刷新；四个联机观看座位保持非对称南北0／东西1计数和目标9正确。复用既有NT-21首个完整墩的公开记录，没有策略、DDS或新出牌选择。API采用公开快照模拟，不能视为实体多设备局域网验证。最终收据位于`artifacts/v322-production/BROWSER_ACCEPTANCE.json`。
